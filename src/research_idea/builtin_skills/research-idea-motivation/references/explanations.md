# 比较困难的不同原因
同一个现象可以有不同原因。explanation_comparison 保留真正不同的解释：怎样产生、最强已有回应改变什么、仍留下什么障碍，以及不同解释对研究必要性的含义。不要把三个同义描述当成三个原因，也不强凑数量。
优先解释正常使用过程中的因果联系，而不是反驳源论文的贡献。对比后在 opportunity 讲清当前最值得追问的原因及它怎样妨碍原目标。revision_reason 说明新材料如何改变原方向；允许改变问题或其来源分类，不为维护旧分类缩小问题。保留 ID 用于追踪同一方向的演化。
困难缺少某能力，不等于把“让 agent 具备该能力”写出来就解释了它。当前任务只提炼研究问题和动机，不要求算法、评分或实验计划。

related_problem_seeds 保留同轮其他困难。深入当前问题时，说明它们是否独立、共同作用或相互依赖。可以暂时分别分析，但不能借“即使另一困难已解决”偷偷取消用户的核心需要。已有方法可以否定某个原因假设；这不自动说明用户希望推进的目标不再重要。

利用定向阅读的 source_understandings 追问：最强已有方法究竟接收什么、怎样取得关键信息、通过什么过程起作用？假设它按原设定成功，当前困难为什么还可能出现？这比要求每篇都暴露不足更能解释研究必要性。跨论文归纳时保留输入条件，不将某一数据集的表现直接当成整个方向的能力边界。
