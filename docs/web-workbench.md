# 本地研究工作台

```powershell
research-idea web --projects ./research-projects --output ./results
```

打开 `http://127.0.0.1:8769/`。保持本地服务运行。`--no-browser` 关闭自动打开浏览器，`--port` 指定端口。一个研究目录同时只运行一个 Web 服务。

## 从一个方向开始

1. 新建研究，输入方向、初步想法和困惑。发送消息先讨论，不自动启动整轮调研。
2. 选择模型与思考档位。默认模型为 GPT 6 astra；档位名称与 Codex 一致。
3. 点击“开始文献调研”。侧边栏根据真实检查点显示明确方向、文献调研、方向讨论、深入分析、问题讨论、研究主张。
4. 方向讨论时继续提问，满意后点击“继续深入分析”。第二次讨论满意后点击“整理研究主张”。
5. 文献页查看实际论文与原文依据，研究主张页查看、导出报告，研究要点页核对持续要求与原话出处。

暖纸色界面减少大面积纯白。阶段操作保持一行，输入框随内容增高，最多显示约五行。窄屏通过左上角按钮展开侧栏。

## 管理研究

新研究默认预算为 **200 次模型调用、300 分钟累计运行时间**。点击研究设置可修改调用上限和时间，Web 中时间直接填写分钟。已有研究保留原预算，升级不会覆盖；等待你阅读或输入的时间不计入运行预算。

鼠标移到研究行，或用键盘 Tab 定位其按钮，可置顶、取消置顶或删除。置顶研究排在前面。删除会把项目移动到项目根目录的 `.trash/`，在“回收站”中可以恢复，不永久删除材料或报告。运行中的研究需先停止。

网页与 CLI 共享 SQLite 记录和项目文件，不复制研究内容到云端。草稿暂存在浏览器本地；发送后的消息、研究结果和活动记录保存在项目中。模型请求与文献检索仍通过原来的研究引擎执行，会使用对应服务和模型额度。

## 运行、停止与恢复

关闭浏览器不会停止后台研究。再次打开网页会读取当前状态。点击“停止运行”终止该研究的工作进程和模型子进程，已成功完成的步骤保留。中断的一步需要重新执行，不显示虚假的完成状态。

另一个 CLI 正在写入同一项目时，网页以运行中显示，拒绝改设置和重复启动，停止该 CLI 需回到其终端。页面上的模型用量与研究预算来自项目记录；等待用户讨论不计入运行时间。

## 实现与验证边界

Web 服务使用 Python 标准库，不需要 Node 构建。只绑定本机回环地址，校验 Host、Origin、请求类型、会话令牌与请求大小。浏览器不能指定任意磁盘路径或执行命令；项目访问限定在服务配置的根目录中。原始模型和论文 HTML 不直接执行。

服务复用 `chat_worker` 和原来的研究引擎。HTTP/进程测试使用明确的合成 worker，验证讨论、两次阶段推进、停止、并发保护、保存、置顶和回收站。它们不构成真实文献调研效果的证据。
