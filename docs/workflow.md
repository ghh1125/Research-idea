# 从研究方向到完整 idea

产品的交付物是一份研究方案。核心是回答**问题为何值得研究，以及方法为什么必要**，让背景、问题、动机、方法一环扣一环，说明与已有工作的区别和第一个值得做的实验。

第一阶段集中解决三个问题：具体研究贡献是否还有空间、方法是否有可预见的实施矛盾、相关论文是否真的回答了同一问题。创新比较分析动机、机制、信息和核心主张；论文的标题和作者声称的效果都不能直接替代正文与实验细节。构思直接使用主张分析，沿着“claim → 实验条件与控制 → 报告结果 → 可支持结论”理解最近工作，再提出有意义的问题、动机和基本方法。

## 主流程

**第一阶段：Background → Problem → Motivation → Idea。** 先解决贡献、意义、基本可行性三个核心问题，到提出 idea 为止。

**第二阶段：Idea → Method。** 才展开具体技术路线、实现步骤、基线和实验方案。第一阶段保留内部可行性推演，帮助提前修正明显障碍；这不等于提前展开完整方法设计。

1. **理解输入。** 结合正式主题、最近八条用户补充和资源条件。讨论中的助手建议不会自动当成用户已经决定的方向。
2. **找到论文。** 方法与策略默认看近十二个月，动机与贡献对照看近六个月，每次运行更新日期。已知的更早相关工作也参与对比。每个查询先取二十篇元数据，合并去重后按词项相关度和日期组织候选池，再用一次模型调用围绕实际研究问题筛选最多四十篇标题/摘要。记录选读原因和正文问题，全流程默认最多精读六篇，不为凑数阅读偏题文章。
3. **读出研究机会。** 阅读者分别回答“有什么方法可借用”和“已有工作究竟回答了什么问题”。原文记录、实验范围、分析卡和研究启发进入共享材料。程序将可用于实验结果、作者明确局限的引用分组交给模型，并继续检查引用类型与来源；只有实际补读了新文本，才再次综合分析卡。
4. **第一阶段提出 idea。** 设计者结合阅读结果，说明具体背景的需要、尚未解决的问题、问题的重要后果、可能原因和基本干预。`positioning` 对每篇最近相关工作写明已经解决什么、仍待回答什么、我们贡献什么；已知动机或贡献重叠在这一任务内修正。`feasibility_sketch` 走通可用输入到关键操作的基本路径，指出关键假设和最早检查。不能依赖推理时的隐藏答案、未开放接口或循环监督，也不能隐藏本来可见的信息来制造问题。资料暂少时仍可提出明确假设和可执行的小试验。
5. **第二阶段探索技术设计。** 从 idea 拆出表示、更新、干预、信号、基线或评测等设计问题，形成最多三条新查询。技术默认看近十二个月，可搜索其他计算机领域。优先复用已读材料，选中的新论文定向读取关键段落，最多三篇进入 `design_transfer`；每篇最多给三个真正有用的选择。只有出现具体未解问题才补读，不重复跑完整论文分析卡。已有方法可直接借鉴，重点是为什么适合当前问题、需要怎样修改。
6. **选择路线并交付。** 用 `design_decisions` 记录采用什么、为什么、相对简单方法的必要性和首测。再展开详细方法与实验协议。审阅者最多提出三个影响方案的意见，每条都有具体改法或区分实验；设计者可采纳、调整、有理由地不采纳或放进实验检验。默认初版加一次修订，`max_rounds` 控制这个设计讨论次数。最终 CLI 和报告优先展示背景、问题、动机、方法、工作差异和第一步验证。

第一阶段的创新判断使用已读工作的具体动机、解释和贡献，方法相似可以作为借鉴；第二阶段以改善技术路线为目的。新文献若揭示明确矛盾，仍应据此改进方案，但不默认追加一整轮泛化查重。正式交付后不再自动启动搜索。

## 跨领域技术如何进入方案

一篇来源论文通过这条记录进入设计：**要回答的设计问题 → 来源技术 → 两个问题的共同结构 → 原技术成立条件 → 本研究的改造 → 对动机的作用 → 简单替代 → 区分实验**。

例如，其他领域的主动感知技术可能适用于为 agent 选择能区分环境规则的观察；需要明确共同的不完全观测结构、可计算信号和更新步骤，再与随机分配观察、固定课程比较。借鉴记录是供设计者选择的技术选项，不是必须堆进方法的模块。原论文事实引用该论文的原文，迁移效果作为我们的预测。

## 角色如何交流

| 角色 | 收到什么 | 交给下一步什么 |
| --- | --- | --- |
| 阅读者 | 选中的论文片段、具体阅读问题 | 第一阶段：问题、动机和贡献边界；第二阶段：技术与迁移条件 |
| 构思者 | 用户方向、论文分析和原文 | 有贡献对照、连贯动机和基本实现路径的 idea |
| 设计者 | idea、技术借鉴、上一轮意见 | 技术选择与理由、完整方法、对照实验、逐条回应 |
| 研究讨论者 | 当前方案及共享文献材料 | 最多三个具体设计问题、建议改法、最有区分力的首测 |

每个任务都是配置后端的独立调用。当前角色串行运行，共用模型与调用预算；使用 Codex 时仍由本地 `codex exec` 执行。角色之间通过结构化材料交流。`review_responses` 将意见与采纳理由对应，`dialogue` 保存每轮交接，修订记录保存实际方法变化。

下一轮讨论同时收到上一轮意见和修改记录，先检查设计者已经如何回应，再决定是否还有具体问题。首测按接口/样本检查、最简单基线、最小机制比较安排；首测预算与后续扩大确认分开，避免把完整论文实验矩阵提前塞进第一步。

意见不是命令。设计者可以说明一个批评为何不适用于当前问题，也可以把它放入首测；不能只回复“已解决”。方法相似不会自动淘汰 idea。若动机确实已有覆盖，可以在用户方向内重构问题或解释，并明确新预测。

## 研究质量要求

- 背景要导出问题：什么具体需求下，什么能力或理解被限制。
- 问题要值得研究：解决后增加什么能力、解释或可理解的边界，而非只有微小指标变化。
- 方法要必要：为什么它作用于原因；最简单可行替代能否同样解决问题。效率改善需要说明它解除的实际约束，不能只罗列 trade-off。
- 方法要对准原因：输入、输出、干预步骤与预期观察能连起来。
- 先检查 agent 已经能看到什么：若直接读取当前状态的简单策略即可完成任务，就要与它比较；若问题归因于旧经验干扰，也应考虑无旧经验的同一 agent。不能通过隐藏本来可见的信息来制造研究动机。
- 实验要有区分力：与最简单替代方案比较，并预先说明什么结果值得继续、什么结果需要修改。
- 小测试要保留真实研究困难：说明它对应什么实际任务或科学问题，以及首测结果如何指导下一步；不能把人为小谜题本身包装成研究贡献。
- 借来的方法要说明来源；提出的假设可以大胆，但不能改写成论文已经报告的发现。

`motivation.basis` 区分有原文依据的观察与待研究的问题假设。前者引用真实证据 ID，后者可以没有引用。所有实际引用仍检查来源身份与原文；新机制的名称、空泛分数或表格完整度都不能替代论证。

资源尚未测量时先设计小规模试验。真正缺少的信号需要修改实现路径，例如从 logits 换成可观察输出；模型不能把不可用信号直接写成可用。方案仍交付，同时写明具体替代设计。

## CLI 呈现

默认展示两个阶段和每一步的结论。第一阶段的 `[concept]` 展示 idea、动机与贡献对照、基本可行性；第二阶段的 `[design]` 展示技术借鉴、路线选择及原因；最后 `[idea]` 展示完整研究方案。`[skill]` 用中文说明分析方法，`[paper]` 给标题与来源，`[evidence]` 给原文依据；同一依据不在每一步反复刷屏。第二阶段检索和阅读不会再显示成第一阶段。

构思按“背景与问题、研究动机、核心思路、基本可行性、已有工作区别”分组；具体实现步骤留到第二阶段，内部可行性推演可以用 `/details` 查看。技术设计逐项显示采用什么和选择理由；最终方案按“问题与动机、方法与贡献、第一项实验”分组。小标题与字段重点使用颜色，正文保持正常文字。论文标题与链接直接跟随相关结论，完整分析也将内部引用转换为可读来源。

- `/config` 显示可读的模型、日期、会议、选文规模和预算。
- `/details` 展开上一步完整分析；`/details on` 显示完整过程，`off` 恢复易读视图。
- 底部三行分别显示模型与进展、调用与时间预算、使用介绍与操作入口。新建交互项目允许单次模型调用等待 20 分钟；总预算仍独立计时，超时提示给出调整与恢复命令。
- 运行时隐藏输入框，Ctrl+C 停止，之后 `/run` 继续。
- 恢复时缓存步骤只提示“已复用”，旧引文不重复刷屏；新分析正常显示，完整旧结果仍可通过 `/details` 和 `/evidence` 查看。
- 累计时间耗尽和单次调用超时分别提示：前者调整 `max_seconds`，后者调整 `timeout_s`；成功检查点保持可恢复。

第一阶段 idea 先保存，再进入技术探索；每项技术借鉴完成后保存，详细方法生成后再保存，随后开展设计讨论。中断时交付已有构思或方法草稿。恢复保留第一阶段来源集合，第二阶段新增论文不会被倒回初轮完整精读；已选论文的下载继续，不重新规划和筛选。相关来源或指导文本变化时重新计算对应任务。修改构思规则时，未改变的正文阅读仍可复用。

会议 PDF 不可用时，可以在本次获取预算内查找同标题的公开预印本；来源记录包含实际阅读版本。全文获取失败按论文 ID 在当前轮去重，补全链接不会触发重复下载。

## 验收方式

自动测试覆盖：资料稀少仍提出假设方案、第一阶段贡献对照与基本实现路径、技术借鉴先于详细设计、第二阶段定向阅读和来源复用、跨论文引用拒绝、具体阅读缺口的有限补读、两种日期窗口、检索与下载中断恢复、意见逐条回应，以及终端的阶段、预算和常驻入口。合成后端用于流程测试；真实模型输出另作运行检查。

借鉴机制与固定源码版本见 [来源对照](sources.md)。
